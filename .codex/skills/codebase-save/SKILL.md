# codebase-save

코드 베이스에서 개발에 필요한 패턴을 발견하고, 개발자가 확인한 의도만 재사용 가능한 프로젝트 지식으로 저장한다. 이 스킬을 만드는 요청과 실행하는 요청을 구분한다. 스킬 생성만 요청받았다면 현재 프로젝트의 패턴 승인 대화를 시작하지 않는다.

## 탐색

사용자가 지정한 영역을 우선 탐색한다. 범위가 없으면 프로젝트 전체를 대상으로 파일과 모듈 목록을 만들고 적용되는 `AGENTS.md`, 기존 개발 규칙·설계 문서, 구현과 테스트를 읽는다. 현재 변경 사항도 확인하되 미완성 코드나 최근 추가된 구현을 확정된 프로젝트 관례로 취급하지 않는다.

프로젝트에 실제로 있는 영역을 찾아 다음을 검토한다. 목록은 탐색 범위를 놓치지 않기 위한 예시이며, 존재하지 않는 영역의 규칙을 만들어내지 않는다.

- API: 라우터 등록, 경로·HTTP 메서드, 계층별 책임, 오류·인증·페이지네이션, 외부 서비스 연결.
- DTO: 요청·응답 모델 위치와 이름, 검증, 필수·선택 필드, 직렬화, 도메인·DB 모델과의 경계.
- 프론트엔드: 페이지·레이아웃·메뉴, 공통 컴포넌트, 스타일, 상태·데이터 요청, 로딩·오류·빈 상태.
- DB: 테이블·모델·관계, 키·제약·인덱스, 마이그레이션, 트랜잭션, 접근 계층.
- 그 밖의 개발 작업: 디렉터리·모듈 경계, 의존성 방향, 명명, 설정·환경변수, 테스트, 빌드·배포·개발 명령.

추가 파일을 찾을 때는 `rg`와 `rg --files`를 우선 사용한다. 의존성 폴더와 빌드 산출물은 제외하고 필요한 원본·생성 설정을 읽는다. 비밀 값과 개인정보를 후보 설명·저장 문서에 포함하지 않는다.

후보마다 실제 구현과 호출부를 확인한다. 가능하면 같은 책임을 가진 다른 구현과 비교하고, 단일 사례뿐이면 그 한계를 밝힌다. 작성자가 명시되지 않은 코드를 사람 또는 AI가 썼다고 단정하지 않는다. 관측된 관례와 개발자의 의도는 확인 전까지 구분한다.

## 한 번에 하나씩 확인

먼저 발견한 영역과 후보 개수를 짧게 알린다. 이후 한 번에 **하나의 독립적인 패턴**만 제시한다. API·DTO·화면·DB 규칙을 한 항목으로 묶어 승인받지 않는다. 후보를 제시하기 전에 승인받을 실제 문구와 저장 위치를 정한다.

후보 설명에는 다음을 포함한다.

- 패턴 이름과 구체적인 저장 문구.
- 적용 범위: 프로젝트 전체인지 특정 계층·기능에 한정되는지.
- 근거 파일과 짧은 실제 예시; 링크와 필요한 위치를 제공한다.
- 관측된 예외·충돌·미완성 부분과 확인이 필요한 의도.
- 저장할 문서 경로와 이를 연결할 `AGENTS.md` 경로. 문서 참조 연결도 저장 흐름에 포함됨을 안내한다.

질문은 “이 패턴을 프로젝트 개발 규칙으로 저장할까요?”처럼 명확하게 하고, `저장`, `수정 후 확인`, `건너뛰기` 선택지를 제공한다. 사용할 수 있는 사용자 입력 도구가 있으면 하나의 질문으로 요청한다. 비동기 도구를 쓸 때도 승인 전 저장하거나 다음 승인 질문을 동시에 열지 않는다. 도구가 없으면 채팅으로 질문하고 응답을 기다린다.

이 스킬이 항목별 확인을 요구하므로 기다리는 경우, 사용자가 이유를 알 수 있도록 `codebase-save`의 해당 지침과 읽은 `SKILL.md` 경로를 짧게 안내한다. 사용자가 직접 지정한 다른 확인 방식은 우선한다.

응답에 따라 다음과 같이 진행한다.

- **저장**: 제시한 문구와 범위 그대로 저장하고, 아래 AGENTS.md 연결 흐름을 수행한 뒤 저장·연결 결과를 확인하고 다음 후보를 제시한다.
- **수정**: 사용자의 내용을 반영한다. “이렇게 바꿔서 저장해”는 해당 수정 문구의 저장 승인이다. 저장 의사가 불분명하면 수정된 문구를 다시 보여주고 확인한다.
- **건너뛰기**: 해당 후보를 저장하지 않고 다음으로 넘어간다. 같은 실행에서 다시 묻지 않는다.
- **대기·불명확한 답변**: 해당 후보는 미승인 상태로 유지한다. 무응답, 경과 시간, 기본 선택값은 승인이 아니다. 추가 읽기 작업은 가능하지만 저장은 하지 않는다.
- **중단**: 이미 승인해 저장한 항목과 남은 후보를 간단히 보고하고 종료한다.

이미 승인된 같은 내용은 다시 승인받지 않는다. 사용자가 명확히 일괄 저장이나 다른 진행 방식을 지시하면 그 지시의 범위만 따르되 미확인 충돌을 임의로 해석하지 않는다.

서로 다른 패턴이 섞여 있으면 실제 사례와 차이를 보여주고 적용 범위를 확인한다. 문서와 코드가 충돌하면 기존 승인 규칙을 조용히 덮어쓰지 않는다. 알려진 버그나 미완성 코드는 현재 상태의 문제로 설명하고 개발 규칙으로 권장하지 않는다. 사용자가 유지하기로 결정한 예외는 그 이유와 한정된 범위를 함께 기록한다.

## 저장

사용자가 지정한 위치와 기존 프로젝트의 문서 구조를 우선한다. 적합한 기존 개발 패턴 문서가 없으면 프로젝트 루트의 `docs/development-patterns.md`에 저장한다. 최초 후보의 저장 질문에 이 경로를 포함한다. 경로는 해당 프로젝트에 한정하며 전역 사용자 규칙에 프로젝트 관례를 섞지 않는다.

문서는 최초 저장 승인 이후에 생성한다. 미승인·거절 후보를 확정 규칙 문서나 별도 파일에 몰래 기록하지 않는다. 승인된 각 항목을 즉시 저장해 대화가 중단되어도 확인된 지식은 남게 한다.

기존 문서를 읽고 의미상 중복을 확인한다. 같은 규칙은 재사용하고, 변경·대체·예외 추가는 그 차이를 제시해 승인받는다. 기존 내용과 작업자의 미커밋 변경을 보존한다.

각 항목에는 다음 정보를 읽기 쉬운 형태로 기록한다.

```markdown
## api-router-registration — API 라우터 등록

- 규칙: 개발자가 승인한 구체적인 작성·등록 방식.
- 적용 범위: 이 규칙이 적용되는 모듈 또는 계층.
- 근거: 저장소 루트 기준 파일 경로와 관련 심볼.
- 예시: 비밀 값 없는 짧은 실제 코드 또는 참조 위치.
- 예외: 확인된 예외와 적용 조건. 없으면 생략.
- 승인일: YYYY-MM-DD.
```

예시의 규칙이나 식별자를 그대로 모든 프로젝트에 복사하지 않는다. 실제 승인 항목을 설명하는 안정적인 식별자를 사용한다. 개발자가 이유를 제공한 경우 선택 이유도 기록한다. 줄 번호는 질문에서 탐색을 돕는 용도로 쓰고, 지속 문서에는 파일 경로와 심볼을 함께 남겨 이후 이동을 추적할 수 있게 한다.

저장 문서가 존재한다고 모든 구현을 즉시 그 규칙으로 바꾸지 않는다. 이 스킬은 기록만 수행하며 제품 코드·DB·의존성·실행 설정을 수정하지 않는다. 승인된 패턴 문서를 `AGENTS.md`에 연결하는 최소한의 문서 수정은 저장 흐름에 포함한다. 다른 스킬 수정은 별도로 요청받았을 때만 수행한다. 요청되지 않은 커밋·푸시·배포는 하지 않는다.

## AGENTS.md 연결

패턴 문서에 승인된 내용을 저장한 뒤, 향후 개발 작업에서 그 문서를 읽도록 적용 범위에 맞는 `AGENTS.md`에 연결한다. 사용자가 연결하지 말라고 지시하면 그 지시를 따른다. 안내한 저장 흐름의 최소 연결 작업에 별도 승인을 반복해서 요청하지 않는다.

1. 프로젝트 전체의 패턴 문서는 프로젝트 루트 `AGENTS.md`에 연결한다. 특정 하위 프로젝트에만 적용되는 문서는 해당 범위의 `AGENTS.md`를 사용한다. 문서 위치가 `docs/`라는 이유로 `docs/AGENTS.md`를 선택하지 않는다. 대상 파일이 없으면 최소한의 문서 참조 안내를 담은 파일을 만든다.
2. 문서 저장이 성공했는지 확인하고, 대상 `AGENTS.md`의 기존 내용과 링크를 읽는다. 기존에 같은 문서를 읽도록 안내하는 항목이 있으면 재사용하고 중복 링크·섹션을 추가하지 않는다. 경로 표현이 달라도 같은 파일을 가리키는지 확인한다.
3. 연결이 없으면 아래처럼 해당 문서를 작업 전에 읽고 관련 규칙을 따르라는 안내와 링크만 추가한다. 링크는 `AGENTS.md` 위치를 기준으로 한 상대 경로를 사용한다. 패턴 본문을 `AGENTS.md`에 복사하지 않는다.
4. 기존 지침, 사용자의 수정, 프레임워크가 관리하는 블록은 보존한다. 자동 생성 블록 안에 내용을 넣지 않는다. 승인되지 않은 후보는 `AGENTS.md`에도 기록하지 않는다.
5. 링크가 실제 문서로 연결되는지 확인한다. 이후 항목을 저장할 때는 기존 연결을 유지하고 다시 추가하지 않는다. 문서 경로 변경이 승인되면 기존 참조를 새 경로로 갱신한다.

프로젝트 루트에 연결하는 기본 예시:

```markdown
## 프로젝트 개발 패턴

코드 작성·수정·검토 전에 [개발 패턴](docs/development-patterns.md)을 읽고 작업 범위에 해당하는 규칙을 따른다. 현재 사용자의 명시적 지시가 우선한다.
```

기존 실행에서 승인받아 저장한 문서를 이어서 관리할 때도 연결이 빠져 있으면 같은 방식으로 보완한다. 승인된 문서가 없거나 저장된 항목이 전혀 없으면 연결 파일을 만들지 않는다. 쓰기 제한 등으로 연결하지 못하면 저장된 문서는 보존하고 실패한 연결 경로·원인을 보고하며, 연결이 완료됐다고 말하지 않는다.

## 확인과 마무리

저장 후 파일을 다시 읽어 승인 문구·범위와 일치하는지, 기존 내용이 보존됐는지 확인한다. 문서에 비밀 값이 없는지와 근거 경로가 실제로 존재하는지 확인한다. `AGENTS.md`의 링크와 작업 전 문서 참조 안내가 존재하고, 상대 경로가 올바르며, 같은 연결이 중복되지 않았는지도 확인한다. 문서 기록만을 위해 앱 전체 테스트를 실행하지 않는다.

완료 시 검토한 영역, 저장한 항목과 문서 링크, 연결한 `AGENTS.md` 경로, 건너뛴 항목 수, 남은 미확인 영역을 간단히 보고한다. 일부 영역만 탐색했다면 전체 프로젝트 패턴을 확인했다고 말하지 않는다. 저장된 개발 규칙 문서는 이후 코드 작성이나 `codebase-review`에서 개발자 의도를 확인할 근거로 사용할 수 있지만, 현재 사용자의 지시보다 우선하지 않는다.
